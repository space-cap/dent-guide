# 아키텍처 문서

## 1. 개요

이 MVP는 **Vercel 환경에서 빠르게 검증 가능한 최소 구조**를 목표로 한다.

핵심 구성은 다음과 같다.

- **Next.js**: 웹 UI + API 라우트
- **Vercel**: 배포 환경
- **JSON 파일**: 가격 데이터 원본
- **OpenAI API**: 애매한 질문 해석 보조

## 2. 시스템 구성

### 2.1 프론트엔드
- 질문 입력 화면
- 답변 리스트 또는 채팅 UI
- 추천 질문 노출 가능

### 2.2 백엔드
- `app/api/ask/route.ts`
- 사용자 질문 수신
- 가격 항목 검색
- 필요 시 OpenAI 호출
- 응답 생성 및 반환

### 2.3 데이터 저장
- `data/prices.json`
- 프로젝트 내부 정적 데이터로 관리
- 수정 후 재배포로 반영

### 2.4 외부 서비스
- OpenAI API
  - 질문 의도 파악
  - 항목명 정규화
  - 동의어 해석 보조

## 3. 요청 처리 흐름

### 3.1 기본 흐름
1. 사용자가 질문을 입력한다.
2. API가 질문 텍스트를 받는다.
3. 서버가 `prices.json`을 로드한다.
4. 키워드/별칭 기반으로 항목을 탐색한다.
5. 매칭되면 `displayType`에 따라 응답을 만든다.
6. 매칭 실패 시, 필요하면 OpenAI로 표준 항목 후보를 추론한다.
7. 후보 항목으로 다시 JSON을 조회한다.
8. 최종 응답을 반환한다.

## 4. 우선 적용할 검색 전략

### 4.1 1차: 규칙 기반 검색
우선 아래 방식으로 검색한다.

- `itemName` 완전 포함 비교
- `aliases` 배열 포함 비교
- 질문 소문자/공백 정규화 후 문자열 비교
- 간단한 키워드 점수화

이 단계는 비용이 없고 빠르다.

### 4.2 2차: OpenAI 보조 검색
1차 검색에 실패하거나 점수가 낮을 때만 OpenAI를 호출한다.

OpenAI에는 다음만 맡긴다.

- 질문을 표준 치료명 후보로 변환
- 모호한 표현을 JSON 항목명 기준으로 정규화
- 필요하면 clarifying question 초안 제안

주의:
- OpenAI는 가격 수치를 결정하지 않는다.
- OpenAI 응답은 검색 보조 데이터로만 사용한다.

## 5. 공개 정책 처리

각 항목은 `displayType`으로 외부 공개 방식을 제어한다.

- `exact`: 정확한 가격 응답
- `range`: 최소~최대 가격 응답
- `inquiry_only`: 상담 안내 응답
- `hidden`: 매칭되더라도 외부 응답 금지

이 구조는 경쟁사에 전체 가격표가 노출되는 문제를 줄이는 데 중요하다.

## 6. Vercel 환경 고려사항

### 6.1 JSON 방식이 적합한 이유
- 읽기 중심 데이터는 Vercel에서 다루기 쉽다.
- 서버리스 함수가 파일을 읽어 응답하는 구조는 단순하다.
- DB 없이도 빠르게 MVP를 배포할 수 있다.

### 6.2 한계
- 런타임 중 파일 수정은 운영 방식으로 부적합하다.
- 가격 수정 시 코드 변경 및 재배포가 필요하다.
- 데이터가 커지고 운영 복잡도가 올라가면 DB 전환이 필요하다.

## 8. 핵심 모듈 책임

### `lib/price-search.ts`
- JSON 데이터 로드
- 질문 정규화
- 별칭 탐색
- 검색 결과 후보 생성

### `lib/response-builder.ts`
- `displayType`에 맞는 사용자 응답 생성
- note, version, fallback 문구 처리

### `lib/openai.ts`
- OpenAI 호출 캡슐화
- 정규화 프롬프트 관리
- 실패 시 안전한 fallback 제공

### `lib/types.ts`
- 가격 항목 타입 정의
- API 요청/응답 타입 정의

## 9. 실패 처리 원칙

### 가격을 찾지 못한 경우
- 추측하지 않는다.
- 유사 항목 후보를 제안하거나 재질문을 유도한다.

예시:
- "해당 항목을 정확히 찾지 못했습니다. 임플란트, 크라운, 레진 중 어떤 치료를 말씀하시는지 알려주시면 더 정확히 안내드릴게요."

### 다수 항목이 동시에 매칭되는 경우
- 상위 2~3개 후보를 보여주고 선택을 요청한다.

예시:
- "크라운은 지르코니아, PFM, 골드로 나뉩니다. 어떤 재질을 원하시나요?"

## 10. 추후 DB 전환 포인트

아래 상황이 생기면 JSON에서 DB로 옮길 시점이다.

- 관리자 업로드가 필요함
- 가격표 업데이트 빈도가 높아짐
- 다지점 운영 시작
- 항목 수가 크게 증가함
- 검색 로그, 버전 관리, 권한 관리가 필요함
