# MVP 요구사항 정의서

## 1. 목표

치과 가격 정보를 사용자가 자연어로 질문하면, 서비스가 **사전에 정의된 JSON 가격표**를 기준으로 관련 가격 정보를 응답하는 MVP를 만든다.

이 MVP의 목표는 다음과 같다.

- 가격 문의를 전화/채팅 상담 이전 단계에서 자동 처리할 수 있는지 검증
- 질문형 인터페이스가 정적인 가격표보다 사용자 친화적인지 검증
- 경쟁사에 전체 가격표를 노출하지 않으면서도 충분한 정보 제공이 가능한지 검증
- 추후 DB 기반 구조로 확장 가능한 최소 설계 마련

## 2. 핵심 원칙

### 2.1 가격 진실 원본
- 가격의 원본은 `prices.json`이다.
- 답변에 사용되는 가격 정보는 반드시 JSON 데이터에서 가져온다.
- OpenAI가 가격을 생성하거나 추정해서는 안 된다.

### 2.2 질문 해석과 가격 조회 분리
- 가격 조회: JSON 검색 로직 담당
- 질문 해석: 키워드 검색 우선, 필요 시 OpenAI 보조
- 답변 생성: 조회 결과를 기반으로 서버가 구성

### 2.3 공개 정책 제어
- 모든 시술 가격을 정확히 공개하지 않는다.
- 항목마다 공개 정책을 둔다.
  - `exact`: 정확한 가격 공개
  - `range`: 범위만 공개
  - `inquiry_only`: 상담 필요 문구만 공개
  - `hidden`: 외부 미노출

## 3. 대상 사용자

### 3.1 환자/잠재 고객
- 특정 치료 항목의 대략적인 비용을 빠르게 알고 싶다.
- 전화하기 전에 가격 감을 잡고 싶다.
- 용어를 정확히 몰라도 자연어로 질문하고 싶다.

### 3.2 내부 운영자
- 개발자가 JSON 파일을 수정해 가격 데이터를 관리한다.
- 아직 관리자 업로드 UI는 제공하지 않는다.

## 4. MVP 범위

## 5. 대표 사용자 시나리오

### 시나리오 A: 정확한 가격 공개 항목
1. 사용자가 "지르코니아 크라운 얼마야?"라고 질문한다.
2. 시스템이 `지르코니아 크라운` 항목을 찾는다.
3. `displayType = exact` 이므로 정확한 금액을 응답한다.
4. 필요 시 주의 문구를 함께 보여준다.

예상 응답:
- "지르코니아 크라운 가격은 50만원입니다. 치아 상태에 따라 최종 비용은 달라질 수 있습니다."

### 시나리오 B: 범위 공개 항목
1. 사용자가 "임플란트 가격 알려줘"라고 질문한다.
2. 시스템이 임플란트 항목을 찾는다.
3. `displayType = range` 이므로 시작가~상한가 형태로 응답한다.

예상 응답:
- "임플란트는 재료와 뼈이식 여부에 따라 99만~149만원 범위입니다."

### 시나리오 C: 상담 유도 항목
1. 사용자가 "뼈이식 비용은?"이라고 질문한다.
2. 시스템이 해당 항목을 찾는다.
3. `displayType = inquiry_only` 이므로 금액 대신 상담 안내를 응답한다.

예상 응답:
- "뼈이식 비용은 상태에 따라 달라져 정확한 비용은 진단 후 안내 가능합니다."

### 시나리오 D: 애매한 표현
1. 사용자가 "앞니 하얀 걸로 씌우는 거 얼마야?"라고 질문한다.
2. 기본 검색으로 정확한 품목 매칭이 어렵다.
3. OpenAI를 사용해 `지르코니아 크라운` 등 표준 항목 후보로 정규화한다.
4. 정규화된 결과로 JSON을 조회해 응답한다.

## 6. 비기능 요구사항

### 6.1 정확성
- 가격 답변은 반드시 JSON에 존재하는 값만 사용한다.
- 매칭 실패 시 추측 응답을 하지 않는다.
- 찾지 못한 경우 재질문 또는 상담 유도를 한다.

### 6.2 속도
- 단순 키워드 검색은 빠르게 응답해야 한다.
- OpenAI 호출은 애매한 질문에만 제한적으로 사용한다.

### 6.3 운영 단순성
- 데이터는 개발자가 `prices.json`에서 직접 수정한다.
- 수정 후 Vercel 재배포로 반영한다.

### 6.4 보안/노출 제어
- 전체 가격표를 표 형태로 공개하지 않는다.
- 질문형 UI만 우선 제공한다.
- 필요시 `hidden` 항목은 절대 응답하지 않는다.

## 7. 성공 기준

다음 조건을 만족하면 MVP 1차 검증에 성공한 것으로 본다.

- 최소 10~30개 시술 항목이 JSON으로 관리된다.
- 대표 질문에 대해 원하는 항목을 높은 확률로 찾는다.
- `exact / range / inquiry_only` 정책이 실제 응답에 잘 반영된다.
- OpenAI 없이도 자주 쓰는 질문은 응답 가능하다.
- OpenAI 보조 시 애매한 표현의 매칭률이 개선된다.
