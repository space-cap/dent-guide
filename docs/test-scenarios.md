# 테스트 시나리오

## 1. 목적

MVP의 핵심 기능이 빠르게 검증되는지 확인하기 위한 수동 테스트 시나리오를 정리한다.

## 2. direct 매칭

### 질문
- 레진 얼마야?
- 스케일링 비용 알려줘
- 지르코니아 크라운 가격 알려줘

### 기대 결과
- `matchType`이 `direct` 또는 `alias`로 반환된다.
- exact 항목은 정확한 원화 금액이 노출된다.

## 3. alias 매칭

### 질문
- 하얀 크라운 얼마야?
- 금니 비용은?
- 치아 심기 가격 알려줘

### 기대 결과
- 별칭 기준으로 적절한 항목이 매칭된다.
- `지르코니아 크라운`, `골드 크라운`, `오스템 임플란트` 등으로 응답된다.

## 4. range 응답

### 질문
- 임플란트 비용 알려줘
- 미백 가격 궁금해
- 인레이 얼마야?

### 기대 결과
- 최소~최대 가격 범위가 노출된다.
- 단일 확정 가격처럼 답하지 않는다.

## 5. inquiry_only 응답

### 질문
- 뼈이식 비용은?
- 골이식 얼마야?

### 기대 결과
- 숫자 가격 대신 상담/진단 안내 문구가 반환된다.

## 6. ambiguous 응답

### 질문
- 크라운 얼마야?
- 보철 비용 궁금해

### 기대 결과
- 바로 하나로 단정하지 않는다.
- 지르코니아, PFM, 골드 등 후보를 제안한다.

## 7. not_found 응답

### 질문
- 사랑니 수면마취 비용 얼마야?
- 교정 월비는?

### 기대 결과
- 없는 가격을 지어내지 않는다.
- 비슷한 항목이 없으면 안전한 fallback을 반환한다.

## 8. OpenAI fallback 확인

### 전제
- `OPENAI_API_KEY`가 설정되어 있어야 함

### 질문
- 앞니 하얀 걸로 씌우는 거 얼마야?
- 빠진 치아 심는 거 비용은?

### 기대 결과
- 직접 매칭 실패 시 AI 보조 해석이 시도된다.
- 최종 가격은 여전히 JSON 항목 기준으로만 반환된다.
